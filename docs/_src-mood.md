基于 dsh-pet 0.3.6 独立桌面版 · 2026年10月22日

# 二、核心问题诊断
经代码审查与实测分析，心情系统“不完善”的体感主要来自以下 6 个问题：
## 问题 1：阈值区间过宽，90% 时间卡在 normal
当前配置 happy=70、tired=30、grumpy=15，normal 区间为 31~69，占 39 个分值点。从基准 50 出发：
- 连续点击 4 次才能达到 happy（50→56→62→68→74）
- workSuccess 需要触发 2 次才能达到 happy，但独立桌面版 workSuccess 基本不触发（依赖 DSH 宿主）
- 实际高频事件只有 click(+6) 和 throwDrag(-4)，幅度太小，用户逗半天心情条几乎不动
## 问题 2：decay 过快，心情刚变化就回归
decayPerSec=0.05 对应时间常数 20 秒，意味着：
- 20 秒后回归 63%
- 1 分钟后回归 95%
- 用户点一下让桌宠开心，去倒杯水回来就已经恢复平静，完全感知不到心情趋势
对比 VPet、拓麻歌子等同类桌宠，心情变化通常是小时级，当前实现是秒级，差距过大。
## 问题 3：喂食不涨心情（最明显的逻辑漏洞）
PET_FEED() 函数中播放了动画、显示了台词（“谢谢款待！心情 +1！”），但代码中并未调用 mood.event(“feed”)。用户投喂鱼干后心情条毫无变化，台词与实际行为矛盾，是最直接的“不完善”体感来源。
## 问题 4：事件过少，独立版大半处于哑状态
| 事件 | 独立桌面版触发频率 | 备注 |
| click | 高 | 用户主动点击 |
| throwDrag | 中 | 拖拽抛掷 |
| workSuccess / workError | 几乎不触发 | 需要 DSH 宿主联动，独立版无工作状态 |
| balanceRich / balanceLow | 30 分钟一次 | 需要配置 DeepSeek API key 且余额有变化 |
| feed（喂食） | 未接入心情 | 功能存在但未写心情偏移 |
| 长时间不理 | 不存在 | 无“被忽视”惩罚机制 |
| 睡觉 / 醒来 | 不存在 | 睡眠动画已存在但未驱动心情 |
| 对话 / 碎碎念 | 不存在 | AI 对话未影响心情 |

## 问题 5：心情只影响分类权重，用户感知太弱
分类权重是概率性变化——happy 时“玩耍”类从 20% 变为 32%，用户不一定能察觉。心情系统未影响以下维度：
- idle 待机动画池（开心时应多蹦跶，困倦时多打哈欠）
- click 点击反应池（开心时被点更开心，生气时被点会烦躁）
- 物理参数（开心时跳跃更高？生气时身体抖动？）
- 碎碎念内容（开心时也可能说出“我好像没什么用”这类低落台词）
- 移动速度与频率（困倦时移动变慢、变少）
## 问题 6：无持久化，重启即清零
每次启动桌宠心情从 50 开始，之前的互动成果全部丢失。data/dsh-pet/memory.json 仅 310 字节，未存储心情值。用户无法形成“长期养成”的感觉。
# 三、同类桌宠参考设计
调研 VPet（虚拟桌宠模拟器）、拓麻歌子经典电子鸡及同类开源桌宠的状态系统，总结可借鉴的设计模式：
| 桌宠 | 状态维度 | 核心机制 | 可借鉴点 |
| VPet | 健康、饱食、亲密度、活跃度、清洁度（5维） | 心情≥90 时好感度 +0.05/周期，≤25 时 -0.05；心情归零后溢出部分扣好感度 | 多维状态联动、好感度长期养成 |
| 拓麻歌子 | hunger、happiness、energy（3维） | 各维度独立衰减；饥饿<28% 扣健康，快乐<24% 扣健康 | 维度间因果关系、阈值惩罚 |
| 经典电子鸡 | 饥饿、快乐、精力、清洁 | 长时间不互动→孤独→生病；离线继续演化 | 忽视惩罚、离线时间计算 |
| Python Desktop Pet | 状态机 + 动画速度 | Happy=快速弹跳，Sad=缓慢下垂，Sleepy=极慢呼吸；动画速度本身传达情绪 | 用动画节奏而非仅内容表达心情 |

关键启示：
- 单维心情不足以支撑“活物感”，至少需要 2~3 个独立维度（心情 + 精力 + 饱食）
- 状态变化应是分钟到小时级，而非秒级
- 用户行为（喂食、抚摸、忽视）必须有明确的状态反馈
- 动画速度、频率、物理参数都应随状态变化，而非仅切换动画内容
- 长期养成（好感度、亲密度）是提升用户粘性的核心
# 四、改进路线（按优先级）
## P0：立刻可改，体感提升最大
| 编号 | 改进项 | 具体做法 | 预期效果 |
| P0-1 | 调整阈值 | happy=60, tired=40, grumpy=25，normal 区间缩至 41~59 | 更容易跨档，心情变化可见 |
| P0-2 | 调慢 decay | decayPerSec 从 0.05 改为 0.005（时间常数约 3 分钟） | 开心能维持十几分钟，有趋势感 |
| P0-3 | 喂食接入心情 | PET_FEED() 中添加 mood.event(“feed”)，偏移量 +8 | 投喂有明确反馈，逻辑自洽 |
| P0-4 | 新增“忽视”事件 | 超过 5 分钟无交互，每次 tick 额外 -0.5/分钟 | 桌宠会因被冷落而低落，鼓励互动 |

## P1：中期完善，丰富表现层
| 编号 | 改进项 | 具体做法 | 预期效果 |
| P1-1 | 心情影响 idle 池 | happy 时 idle 加入“可爱宅舞”“轻快摇摆舞”；tired 时加入“原地小憩沉眠”“哈欠连天”；grumpy 时加入“看表叹气” | 待机状态直接反映心情 |
| P1-2 | 心情影响 click 反应 | happy 时被点优先“开心跃动/挠痒笑”；grumpy 时被点优先“傲娇生气”，连续点击额外扣心情 | 互动有情绪反馈 |
| P1-3 | 碎碎念按心情筛选 | 将 idleLines 按档位分组，happy 说开心话，grumpy 说气话，tired 说困话 | 台词与心情一致 |
| P1-4 | 心情持久化 | 每次心情变化写入 memory.json，启动时恢复 | 形成长期养成感 |
| P1-5 | 睡觉/醒来事件 | 进入睡眠动画时 mood.event(“sleep”)(-5)，醒来时 mood.event(“wake”)(+3) | 作息影响心情 |

## P2：长期演进，从“心情”升级为“状态系统”
| 编号 | 改进项 | 具体做法 | 预期效果 |
| P2-1 | 新增精力维度 | 独立于心情，醒着缓慢下降，睡觉恢复；精力低时自动播困倦动画、移动变慢 | 模拟真实作息 |
| P2-2 | 新增饱食维度 | 喂食恢复，随时间下降；饿了主动说“想吃东西”，饿太久扣心情 | 喂食有长期意义 |
| P2-3 | 好感度系统 | 借鉴 VPet：心情长期高位时好感度缓慢增长，低位时下降；好感度解锁新台词/新动作 | 长期养成目标 |
| P2-4 | 离线演化 | 关闭时记录时间，下次打开按离线时长衰减精力/饱食，并触发“我饿了好久了”台词 | 真实感增强 |
| P2-5 | 多宠互动 | 多开时宠物相遇触发互动动画，互相影响心情（贴贴+心情，打架-心情） | 多开有意义 |

# 五、建议参数配置（P0 级，可直接替换）
将 config/main-config.jsonc 中的 moods 段替换为以下内容：
"moods": {
  "enabled": true,
  "decayPerSec": 0.005,
  "thresholds": { "happy": 60, "tired": 40, "grumpy": 25 },
  "specs": {
    "happy": {
      "weights": { "玩耍": 1.8, "小动作": 1.4, "吃什么": 1.2, "时节": 0.8, "文字": 0.5 },
      "anims": ["点击回应-开心跃动", "点击回应-元气挥手", "蓝鲸现世"]
    },
    "normal": { "weights": {} },
    "tired": {
      "weights": { "小动作": 1.6, "文字": 1.3, "吃什么": 0.9, "玩耍": 0.3, "时节": 0.4 },
      "anims": ["哈欠连天", "迷糊犯困", "睡眼惺忪"]
    },
    "grumpy": {
      "weights": { "小动作": 1.3, "玩耍": 0.2, "吃什么": 0.3, "时节": 0.2, "文字": 1.2 },
      "anims": ["看表叹气", "玩游戏气急败坏", "摸鱼被抓"]
    }
  }
}
核心改动说明：
- decayPerSec: 0.05 → 0.005（回归速度慢 10 倍，心情维持更久）
- happy: 70 → 60（更容易进入开心状态）
- tired: 30 → 40（深夜更容易进入疲倦状态，与 NIGHT_REST=30 配合）
- grumpy: 15 → 25（烦躁状态更容易触发）
- 各档权重倍率适当放大，增强分类偏向的感知度
# 六、代码修改要点
## 6.1 喂食接入心情（P0-3）
文件：app/runtime/electron-helper/sprite.js，PET_FEED() 方法内添加：
// 在播放动画和台词之后添加
const feedMood = this.mood.event('feed');
if (feedMood) this.moodCue(feedMood);
同时在 app/src/shared/mood.ts 的 MOOD_EVENTS 中添加：
feed: 8,  // 投喂小鱼干
## 6.2 忽视惩罚（P0-4）
在 sprite.js 的 tick 循环中，记录最后一次交互时间，超过阈值时在 mood.tick 之外额外扣减：
// tick 中
const idleMs = now - this.lastInteractionAt;
if (idleMs > 5 * 60 * 1000) {
  this.mood.value = Math.max(0, this.mood.value - 0.5 * (dt / 60));
  this.syncMood(); // 内部方法，重算档位并触发 cue
}
## 6.3 心情持久化（P1-4）
在 MoodState 中添加 save/load 方法，每次 event/tick 后异步写入 memory.json：
// 保存
fs.writeFile(memoryPath, JSON.stringify({ mood: this.value, updatedAt: Date.now() }));
// 启动时恢复
const saved = JSON.parse(fs.readFileSync(memoryPath));
this.value = saved.mood ?? MOOD_BASE;
# 七、总结
当前心情系统的架构设计是合理的——连续值 + 倍率方案在不新增素材的前提下实现了情绪偏向，且向后兼容性做得很好。问题主要出在参数调校和事件覆盖度上：
- 阈值太宽 + decay 太快 = 用户几乎看不到心情变化
- 事件太少 + 独立版哑事件 = 心情缺乏驱动力
- 喂食不涨心情 = 最直观的功能逻辑断裂
- 只影响分类权重 = 表现层感知不足
- 无持久化 = 缺乏长期养成动力
建议按 P0 → P1 → P2 顺序推进。P0 的四项改动（调阈值、调 decay、喂食接心情、忽视惩罚）可在 1~2 小时内完成，且能立刻让用户感受到“心情系统真的在工作”。P1 丰富表现层，P2 则是从单维心情升级到多维状态系统的长期演进方向。
